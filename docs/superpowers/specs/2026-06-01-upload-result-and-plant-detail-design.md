# 上传结果页 & 植物详情页 设计说明书

> 合并设计：第一轮讨论 + 用户详细设计说明书  
> 日期：2026-06-01

## 设计目标

用户上传一张图片后，系统完成 OCR + AI 识别，不只是提示"上传成功"，而是让用户明确感受到：

1. 这张图片已经被 AI 小园丁理解了
2. 它被种进了哪个一级花圃和哪株二级主题植物
3. AI 提取出了哪些标签、摘要和结构化字段
4. 它让植物产生了什么成长变化
5. 如果信息不完整，需要补水
6. 用户可以继续查看植物、补充信息或继续投喂

**核心表达："这不是上传文件成功，而是一条灵感被种进花园，并让植物成长了。"**

## 一、数据模型变更

### 1.1 seeds 表新增字段（migration: 002）

| 字段 | 类型 | 说明 |
|------|------|------|
| `image_url` | TEXT | Supabase Storage 图片 URL |
| `title` | TEXT | AI 生成种子标题（≤12字） |
| `summary` | TEXT | AI 摘要（≤80字） |
| `extracted_fields` | JSONB | AI 提取的结构化字段 |
| `missing_fields` | TEXT[] | 种子级缺失字段 |
| `branch` | TEXT | 归属分支名，如「住宿」「餐厅」 |

### 1.2 Supabase Storage

- Bucket: `seed-images`，路径 `{user_id}/{seed_id}.{ext}`
- 公开访问，通过 URL 加载缩略图/原图

### 1.3 TypeScript 类型扩展

详见 `src/types/index.ts` 的 Seed 接口扩展。

### 3.3 植物主视觉规则

- 只展示当前阶段植物插画，不展示完整生命周期组图
- 根据 `plantFamily` + `stage` 渲染 SVG 插画
- 5 family × 5 stage = 25 种形态
- 背后柔光圆形背景
- 使用 Framer Motion 微动效（叶片摇曳/花瓣飘落）

### 3.4 SeedCard 灵感卡片

每条灵感卡片展示：
- 原图缩略图 / 链接预览图 / 文本图标
- AI 生成标题
- AI 摘要（2行截断）
- 来源类型 + 时间
- OCR 原文（折叠展开）
- 提取字段预览
- 标签
- 缺失字段
- 本次贡献
- 操作：补充信息 / 查看原图 / 移动到其他植物

## 四、API 设计

### 4.1 `/api/upload` POST（新增）
- 接收 FormData（图片文件）
- 上传到 Supabase Storage `seed-images/{user_id}/{seed_id}.{ext}`
- 返回 `{ imageUrl, thumbnailUrl }`

### 4.2 `/api/classify` POST（扩展）
- 扩展 AI prompt，新增返回：`title`, `summary`, `extractedFields`, `branch`
- Mock 模式同步适配

### 4.3 `/api/seed` POST（扩展）
- 接收新字段：`imageUrl`, `title`, `summary`, `extractedFields`, `missingFields`, `branch`
- 创建种子后调用 `recalcTopic` 重算主题生长值
- 返回：`{ seed, topic, growthNarrative }`

### 4.4 `/api/seed/[seedId]` PATCH（扩展）
- 补充信息后重算 completenessScore + growthScore
- 返回 `{ seed, topic, growthNarrative }`

### 4.5 `/api/seed/[seedId]/move` POST（新增）
- 移动种子到其他 topic
- 重算两个 topic 的生长值

## 六、设计边界

**不要做成：** 普通上传成功页、文件管理页、后台详情页、复杂游戏养成页、任务打卡页

**要做成：** 灵感被种下的仪式感、植物成长反馈、AI 识别结果可理解、缺失信息可补水、开花后可采摘
